# 07: Public article reading

**What to build:** Readers browse the public Article side: a home page of recent Articles, hierarchical Category browsing with breadcrumbs, Tag pages, a time archive, and on-site search with highlighted matches. The Article page renders the full core block set — code with syntax highlighting, images at original ratio with a lightbox for zoom (Esc closes, arrows navigate, focus managed), very tall images contained instead of cropped — plus previous/next navigation. Permanently deleted Articles answer 410; archive and search pages carry noindex; the sitemap lists only indexable Articles; shared links carry correct title, summary, and image metadata. Everything reads comfortably on phones.

**Blocked by:** 02 — Locale routing & site chrome; 05 — First published Article

**Status:** ready-for-agent

- [x] The home page lists recent published Articles with title, summary, publish time, and Category.
- [x] Category browsing works as a tree with breadcrumbs showing the path; Tag pages list all Articles sharing a Tag; an archive lists all Articles by time.
- [x] Search matches title, body, Tag names, and Category names, filtered to the current Locale, and highlights the matched keywords; the search page is noindex.
- [x] The Article page renders all core blocks; code blocks get syntax highlighting and correct monospace layout; images show at original ratio clamped to a maximum width; extremely tall images are contained by a viewport-height limit rather than cropped.
- [x] Clicking a body image opens the shared lightbox: original size, Esc to close, arrow keys to navigate, focus managed.
- [x] Every Article page ends with previous/next or related-Article navigation.
- [x] Old Slugs resolve to the current Article URL; permanently deleted Articles answer 410; everything else unknown answers 404.
- [x] Archive pages carry noindex; the sitemap contains only indexable Article URLs; shared-link metadata (title, summary, image) is emitted.
- [x] Article pages are mobile-first: comfortable reading on phone widths.

## Comments

Built on top of 05 without touching its Article data model: no migration, no new dependency, no second renderer. Every Reader list goes through one new service module, `src/services/reading.ts`, which reuses `article_translation` joins plus the existing `loadCategoryViews` / `loadTagViews` / `listCategoryTree` / `listTags` helpers, and the Article page renders through ticket 05's `renderArticleBody`.

**The one list rule** (confirmed with the product owner): every Reader surface — home, Category, Tag, archive, search, previous/next, sitemap — lists only Articles that have a version in the current Locale. A Content Fallback page is reachable by URL but never linked from a list. Search, archive and fallback pages additionally carry noindex.

- **Domain**: `search.ts` (keyword splitting, `<mark>` segmentation with merged overlapping ranges, `LIKE` wildcard escaping), `category-path.ts` (path segments, one breadcrumb per level, descendant containment), `article-time.ts` (site-timezone month buckets, publish date and month labels), `public-paths.ts` (home/categories/tags/archive/search URL map and the two parsers — `article-url.ts` from 05 still owns `/articles/{slug}`).
- **Reading service**: `listRecentArticles`, `listReaderCategories`, `findReaderCategory`, `findReaderTag`, `listArchiveArticles`, `searchArticles`, `findArticleNeighbours`, `listIndexableArticlePaths`, `listTombstonedSlugs`, `resolveBodyImages`.
- **Search** is a `LIKE` scan, as the spec asks, and it reads the *derived Markdown* column (which exists for exactly this) plus title, Tag names and Category names. Every keyword must match somewhere; a title hit sorts first, publish order breaks the tie.
- **Category pages** list their own Articles *and* their descendants', show child Categories with counts, and render a real breadcrumb list with the last crumb as `aria-current="page"`.
- **Previous/next** are `older`/`newer` in the service (unambiguous names) and are ordinary Reader neighbours: they skip Articles without a version in the current Locale, so a fallback page never appears in the chain.
- **Renderer extension (05's `render-article.ts`, no second path)**: `renderArticleBody(bodyJson, { resolveImage })` now takes an optional resolver the page backfills from the Asset store. It emits `data-original` (the untouched upload), the true `width`/`height`, and `class="article-image article-image--tall"` when height/width exceeds `TALL_IMAGE_RATIO` (2). 09 keeps injecting new nodes through the same `nodeMapping` seam — nothing in this ticket narrows it.
- **Shared lightbox**: `src/components/lightbox.tsx`. `Lightbox({ images, startIndex?, labels, onClose })` with `LightboxImage = { src, original?, alt }` — mounting it means open, unmounting restores focus. Esc closes, ArrowLeft/ArrowRight wrap, Tab is trapped, the page behind does not scroll, and the image is `original ?? src`. Ticket 08 mounts it directly from the Feed gallery. `ImageZoom({ labels, children })` is the Article-body adapter: it delegates clicks and Enter/Space on any `<img>` inside the server-rendered body, so the body HTML stays server-produced.
- **Metadata** is derived from the request through `absoluteUrl`/`requestUrl` (no hardcoded domain): canonical, `alternates.languages` for **only the Locale versions that exist**, OG/Twitter title + summary + first body image, and `robots: noindex` on archive, search and Content Fallback pages. The fallback page's canonical points at the default-Locale URL, which is the real version.
- **Sitemap** at `/sitemap.xml` (`src/app/sitemap.ts`) lists one URL per *existing* Locale version of each visible Article. The `.xml` suffix already keeps it out of the locale redirect.
- **410 vs 404 — the one decision worth flagging**: a Next.js 15 page can only answer 200 or 404 (`notFound()`); `next/navigation` exposes 401/403/404 interrupts and nothing for 410, and the Edge middleware cannot read SQLite. Rather than degrade the spec's "permanently removed ≠ not found", the middleware asks a Node route for the tombstone Slugs (`GET /api/public/gone-slugs`) and answers 410 itself with `src/http/gone.ts` (a small, chrome-free, locale-aware page with `x-robots-tag: noindex`). It caches the list for 30 s per Edge isolate, fetches at most once per window, and fails open — a failed lookup falls through to the page and 404. The page's own `permanently-removed` branch calls `notFound()` as a backstop.
- **Content Fallback notice (10 extends this, does not rebuild it)**: the Article page renders `<p class="reader-notice" role="note">` from `t.reader.fallback.notice` — "this article has no {requested} version yet; what follows is its {shown} version" — and nothing else. No switcher marks, no panel, no per-work availability: that is ticket 10's, and it can replace this one paragraph without touching the data path (`findReadableArticle` already reports `fellBack` and `indexable`).
- **`vitest.config.ts`** gained two things so renderer output can be asserted for components: `.test.tsx` in `include`, and `oxc: { jsx: "automatic" }` (tsconfig keeps `jsx: "preserve"` for Next, so tests have to transform JSX themselves).

Validation: `npx tsc --noEmit` clean; `npm run lint` 0 errors (the one pre-existing `eslint.config.mjs` warning); `npm test` 41 files / 370 tests green (82 new: domain 32, reading service 25, renderer 4, components 14, middleware 4, `goneResponse` 3); `npm run build` succeeds with every public route dynamic (`ƒ /[locale]`, `/[locale]/articles/[slug]`, `/[locale]/categories/[[...path]]`, `/[locale]/tags/[slug]`, `/[locale]/archive`, `/[locale]/search`, `/sitemap.xml`, `/api/public/gone-slugs`) and Middleware at 40.4 kB — note the pages must stay `force-dynamic`; with `generateStaticParams` present Next labelled them SSG and prerendered them at build time, so those four pages deliberately have no `generateStaticParams`.
