# 05: First published Article

**What to build:** The Author logs in and writes a long-form Article in a rich editor — headings, inline emphasis (bold/italic/strikethrough/underline/highlight), lists, task lists, quotes, code blocks, links, dividers, images — using slash commands, Markdown keyboard shortcuts, and Markdown paste, with undo/redo. They set title, Slug, summary, Category, and Tags; drafts save automatically; preview shows the published form. Publishing happens immediately or at a future Publish Time judged by the site timezone; Articles can be archived or permanently deleted with confirmation. Slugs renamed after publishing keep every old Slug resolving to the same Article; a permanently deleted Article answers 410, distinct from 404. Every publish writes a Revision snapshot; throttled edit-time snapshots are pruned automatically.

**Blocked by:** 01 — Project foundation & ops contract; 03 — Author auth & admin shell; 04 — Asset pipeline

**Status:** ready-for-agent

- [x] The editor provides the core block set with Markdown keyboard shortcuts and slash-command insertion; pasting Markdown converts to blocks; undo/redo covers editing operations.
- [x] The meta panel sets title, Slug, summary, one Category (selectable from the tree), and multiple Tags; new Categories and Tags can be created inline while writing.
- [x] Images insert into the body via the shared picker and render in the editor.
- [x] Drafts save automatically: edits first land in browser-local storage, then sync to the server on a throttle; throttled saves do not create Revision snapshots.
- [x] Preview renders the Article exactly as it will appear when published.
- [x] Publishing makes the Article visible to Readers; an Article with a future Publish Time stays hidden until that moment, judged by the site timezone — Publish Time is not a fourth Publication State.
- [x] Archiving removes the Article from lists while its URL stays reachable; permanent deletion requires a confirmation step and its URL later answers 410.
- [x] Renaming the Slug after publishing keeps every previous Slug resolving to the same Article.
- [x] Publishing always creates a Revision snapshot; edit-time snapshots are throttled and pruned to "all publish snapshots plus the latest N automatic ones".
- [x] Each work stores its translation shape from day one: at most one translation row per Locale (unique constraint) and a recorded `defaultLocale`; a Reader can never see an unpublished or not-yet-due Article.

## Comments

Implemented on top of 04, with one reading of the spec confirmed with the dispatcher before the UI landed: **Publish Time is not a fourth Publication State**. Publishing stores `publicationState = "published"` plus a `publishTime` column, and visibility is derived (`visible | scheduled | draft | archived`); a future Publish Time leaves the Article `published` but hidden until that instant in the single site timezone. There is no scheduler and no `scheduled` enum value. The derived label now reports `scheduled` only for a published-and-not-yet-due Article — a draft reports `draft` even if it somehow carries a publish time, because it can never go live on its own.

**Contract for 06 / 07 / 09 / 10 / 11** (all in `src/services/articles.ts` unless noted):
- `findReadableArticle(ctx, {slug, locale})` → `{kind:"found", article, translation, fellBack, indexable}` | `{kind:"permanently-removed"}` | `{kind:"not-found"}`. 07 renders 410 for `permanently-removed` and 404 for `not-found`. `indexable` is already false for archived, for a not-yet-due Article and for a Content Fallback page, so 07/10 should trust that one boolean instead of re-deriving.
- `listPublishedArticles(ctx)` → visible Articles, newest Publish Time first (drafts, scheduled and archived excluded).
- `resolveArticleSlug(ctx, slug)` → found with `slugKind: "current" | "historical"`, or `permanently-removed`, or `not-found`. Archived resolves as found.
- `buildArticlePath({locale, slug})` / `parseArticlePath(pathname)` in `src/domain/article-url.ts` — the URL shape is `/{locale}/articles/{slug}`, percent-encoded; 07 owns the route.
- Content rendering: `renderArticleBody(bodyJson)` in `src/editor/render/render-article.ts` (server-only, Shiki + srcset). `src/components/article-body.tsx` renders the HTML with the `.article-body` styles. The extension list lives only in `src/editor/extensions.ts`; 09 appends its power blocks there and injects `nodeMapping` through `render-article.ts`.
- Translations: `addArticleTranslation`, `saveArticleTranslation`, `removeArticleTranslation`; the uniqueness constraint is the `article_translation` primary key `(article_id, locale)`.
- Revisions: `listRevisions`, `captureAutomaticRevision` (throttled), `restoreRevision`, `publishArticle` (always snapshots every translation).

- **Domain** (`src/domain/`): `ulid.ts` (Crockford base32, verified against the ULID specification example), `publication.ts` (visibility predicate + `isVisibleToReader` / `isReadableByUrl` / `isIndexable`), `site-time.ts` (wall-clock ⇄ instant in the site timezone, DST-correct, rejects non-existent local times), `slug.ts` (Unicode-aware normalisation, safety, collision numbering), `article-url.ts`, `revision.ts` (pruning policy + snapshot throttle), `rich-text.ts` (ProseMirror document validation), `localised.ts` (`pickLocalised` for Content Fallback display).
- **Data** (migration `0003_ambitious_orphan`): `article`, `article_translation`, `article_revision`, `article_slug`, `article_slug_history`, `article_tag`, `category`, `category_translation`, `tag`, `tag_translation`. ULID primary keys, ISO text timestamps, `parentId` self-reference for the Category tree with a unique locale-neutral `path`. `article_slug` and `article_slug_history` reference `article` with `ON DELETE SET NULL`, so a permanently deleted Article keeps every Slug it ever answered on, as a 410 tombstone. The harness schema test asserts all 16 tables and the new column lists.
- **Services**: `src/services/articles.ts`, `categories.ts`, `tags.ts` — create/update/translate/publish/archive/delete, Slug rename with history, revision snapshot/restore/prune, asset reference sync through `syncAssetReferences` (`contentKind = "article"`), and Category/Tag inline creation. Pruning keeps every publish snapshot plus the latest 20 automatic ones; automatic snapshots are throttled to one per 5 minutes per Article; autosave itself never writes a revision.
- **HTTP** (no Server Actions, each adapter verifies the session itself): `GET|POST /api/admin/articles`, `GET|PATCH|DELETE /api/admin/articles/<id>`, `POST /api/admin/articles/<id>/translations`, `PUT|DELETE /api/admin/articles/<id>/translations/<locale>`, `POST /api/admin/articles/<id>/publication` (`publish` | `archive` | `unarchive`), `GET|POST /api/admin/articles/<id>/revisions`, `POST /api/admin/articles/<id>/revisions/<revisionId>/restore`, `POST /api/admin/articles/<id>/preview`, `GET|POST /api/admin/categories`, `GET|POST /api/admin/tags`. Errors are `{error:"<kebab-code>"}`: 401 `unauthorized`, 404 `not-found`, 409 `duplicate-locale` / `duplicate-slug` / `default-locale` / `last-translation` / `not-published`, 400 `invalid-json` / `invalid-locale` / `invalid-slug` / `invalid-publish-time` / `unknown-category` / `unknown-tag`. The derived Markdown column is always computed server-side from the JSON; a client-supplied Markdown value is neither trusted nor accepted.
- **Editor**: TipTap 3.32 (starter kit, highlight, image, task list) with Markdown input rules from the kit, slash commands via `@tiptap/suggestion` + `props.mount`, Markdown paste conversion via `MarkdownManager.parse`, undo/redo from the kit; images inserted through the shared `AssetPicker` keep the literal `/media/<id>/display.webp` address in `src` (so `extractAssetIds` keeps finding them) and get `srcset`/`sizes`/`loading="lazy"` at render time.
- **Admin**: `/admin/articles` lists Articles with Slug, state and Locales; `/admin/articles/[id]` is the editor with title, toolbar, meta panel (Slug, summary, default Locale, Category tree select, multiple Tags, inline Category/Tag creation), a Locale switcher that can add a missing version, autosave (IndexedDB first, then a 2 s server throttle), a preview panel that renders through the same server renderer as the published page, and the publication panel (publish now, schedule at a site-timezone wall clock, archive/unarchive, two-step permanent delete). `admin.articles.*` was added to both `zh` and `en` with identical structure.
