# 12: Accessibility & display polish

**What to build:** All public pages meet the accessibility baseline: WCAG 2.1 AA contrast in both themes, complete keyboard-only reading and navigation with visible focus and a skip-to-content link, lightbox and gallery keyboard and focus behaviour, and no unnecessary motion under `prefers-reduced-motion`.

**Blocked by:** 07 — Public article reading; 08 — Post feed

**Status:** ready-for-agent

- [x] Light and dark themes each meet AA contrast for body text and interactive elements.
- [x] Every reading and navigation flow works with the keyboard alone; a skip-to-content link exists; focus is always visible.
- [x] The lightbox closes with Esc, navigates with arrow keys, and manages focus (trap while open, restore on close); the Feed gallery supports arrow keys.
- [x] With `prefers-reduced-motion` enabled, non-essential animations are disabled.
- [x] Phone-width reading is verified for Article pages and the Feed.

## Comments

Presentation, semantics and interaction only: no migration, no new dependency, no new route, no second styling system. Everything stays on the theme tokens in `src/app/globals.css`; the CSS changes are additive wherever another ticket already had a block (`#line` token, skip link, phone rules, one `:focus-visible` rule, one reduced-motion query) and no page was restructured.

**The contrast proof is a test, not a claim** — `src/app/globals-css.test.ts` parses the token values out of `globals.css`, computes WCAG relative luminance in the test, and asserts every pair the sheet actually uses, in both themes. Measured (light / dark): `fg` on `bg` 15.80 / 15.65, `muted` on `bg` 6.39 / 7.39, `accent` on `bg` 5.19 / 7.32 (link text, ≥4.5), `bg` on `accent` 5.19 / 7.32 (label on a filled control, ≥4.5), `accent` on `bg` 5.19 / 7.32 (focus ring, ≥3), `line` on `bg` 3.73 / 4.07 (control boundary, ≥3). The maths is pinned to published WCAG values (`#ffffff`/`#000000` = 21, `#767676`/`#ffffff` = 4.54) so it cannot silently drift with the implementation.

- **What actually failed AA** was not a text token — 07/08's four tokens already cleared 4.5:1 — it was the *interactive boundary*: the Post composer's writing surface was framed in `color-mix(--muted 22%, --bg)`, i.e. **1.37:1 light / 1.47:1 dark**, under 1.4.11's 3:1 for a component boundary. The four-token system had no boundary colour to reach for, so it gained exactly one: **`--line`** (`#7d8590` light, `#6e7781` dark), documented in the stylesheet as the control-boundary role and used by `.post-composer-surface` only — existing `var(--muted)` borders (6.39 / 7.39) already pass and were left alone. Decorative container borders (Feed card, callout, `<details>` frame) stay faint on purpose: 1.4.11 governs components, not grouping.
- **Two more structural guards** keep it from regressing: text colour may only be one of the five tokens (`color:` is token-or-`inherit` everywhere), and no rule that sets `outline: none` may exist without a matching `:focus-visible` ring — that is how the composer's invisible focus was found.
- **Skip link**: `src/components/skip-link.tsx` (`SkipLink`, `MAIN_CONTENT_ID`) is the first focusable thing in every public document, and all seven public page modules (`home`, `archive`, `search`, `feed`, `tags/[slug]`, `categories/[[...path]]` — two `<main>`s, `articles/[slug]`) render `<main id={MAIN_CONTENT_ID} tabIndex={-1}>`. A test reads those page files and requires one target per `<main>`, so "the anchor points at an id nobody renders" cannot come back. Message key: `chrome.skipToContent` (`跳到正文` / `Skip to content`) — appended inside `chrome`, zh and en in lockstep.
- **Feed gallery**: 08's cells were *not* keyboard-operable — the track handled the arrows but every open control was `tabIndex={-1}`, so a keyboard user could scroll a gallery and never open a picture. Rebuilt as one Tab stop with a roving `tabIndex`: the picture on view is focusable, ArrowLeft/ArrowRight move focus cell to cell (`galleryNextIndex`, stopping at the ends), Enter/Space activate the native button, the `3/9` fraction is `aria-hidden` while the localised `Image 3 of 9` sentence is the polite live region, and each cell's accessible name is that same sentence rather than a file name. The track is now a real `<ul role="list">` with `<li>` cells. The ring is drawn on the cell (`:focus-within`) because the cell clips the picture, with `0.25rem` of track padding so the scroller cannot crop it.
- **Lightbox**: Esc, arrow keys, Tab trap and focus restoration existed from 07; the missing pieces were the index maths being inline and untestable, focus restoration assuming the browser focused the clicked button (Safari does not), and modified arrows (`⌘←`) being swallowed. Now `wrapIndex`/`focusTrapTarget` are pure exported functions with their own tests, the key listener ignores modified keys, and the Feed passes `returnFocusTo={cellRefs.current[opened]}` so focus lands on the exact cell it was opened from. Article body images also gained `aria-haspopup="dialog"` and — since they may have no description — a name (`labels.dialog`) for the button role `ImageZoom` gives them.
- **Reduced motion**: two layers, both asserted. Seven transition blocks live inside `@media (prefers-reduced-motion: no-preference)` (the test fails if any `transition`/`animation` declaration escapes a motion query), and a new `@media (prefers-reduced-motion: reduce)` block shortens every duration to `0.01ms`, caps iteration at 1 and forces `scroll-behavior: auto` — shortening rather than removing keeps `transitionend`/`animationend` firing, so nothing that listens for them breaks; the gallery's `scrollIntoView` already picks `behavior: "auto"` under the preference and now does so for arrow-key focus moves too.
- **Focus visibility**: one ring (2px `--accent`, 2px offset) on links, buttons, fields, gallery cells and dialog controls in both themes; `.post-composer-surface` and `.article-editor-surface` (writing surfaces that remove the UA ring) both draw it, and the editor's offset now matches.
- **Semantics**: the Tag heading's `#` is `aria-hidden` (it was read out as a stray symbol); galleries and Tag rows are lists; `<time datetime>` was already on Article, list and card; landmarks (`header`/`nav[aria-label]`/`main`) were already correct; the lightbox is `role="dialog" aria-modal="true"` on an `aria-label`. **Alt text**: the Author's file name was being used as the picture's description in two places (editor image insert, `feedView`). It is metadata, so both now produce `alt=""` and the surrounding control carries the name — the Feed cell by position, the Article zoom control by the viewer it opens. There is no authored description field yet; when one exists it drops into the same attribute.
- **Admin keyboard (in scope)**: the Post composer's writing surface had `outline: none` and no replacement (invisible focus, now fixed); its boundary failed 1.4.11 (now `--line`); the Article conflict panel is a dialog with no focus management — it now takes focus on open, closes with Esc and returns focus to the control that opened it (its `aria-modal="false"` stays, it is an inline panel, not a modal). Admin wide-screen ergonomics were not touched.
- **Phone width** (360–430px): long unbroken strings now wrap (`overflow-wrap: anywhere` on `.article-body` and `.post-body`) instead of pushing the document sideways; `.post-body pre` scrolls inside its own box like the Article body already did; reader controls that were 20–30px tall are 44px boxes (`header a`, `header button`, `.post-expand`, `.feed-more-button`, `.post-tag`, `.reader-tags a`, the three lightbox buttons) and reader text that sat at 12.8–13.6px is at the 14px floor (`.post-time`, `.post-gallery-counter`, `.post-tag`, `.reader-tags`). The 85%-wide gallery cell + its own scroller means the page itself never scrolls horizontally.

**Accepted scope notes (explicit, not silent)**
- **Ticket 09's fold-block toggle has no accessible name.** Its node view is built outside React and `articleExtensions` is a static schema shared with the server renderer and the Markdown derivation, so a translated label means threading two strings through the extension factory (4 call sites + a new message namespace) — 09's area, and it is being written in parallel. Left as declared: the button keeps `▸`/`▾` + `aria-expanded` (state announced, name missing). Closing it later: make `articleExtensions` a factory that accepts `{ expand, collapse }` and pass them from the editor and the composer. Public Article pages are unaffected — they render native `<details>/<summary>`, which needs no JavaScript and is keyboard- and AT-complete.
- **A wide Author table can still exceed a phone column.** `.article-body table { width: 100% }` does not stop min-content overflow; the fix is a scroll wrapper element in `render-article`'s table mapping (09's markup). `display: block` on `<table>` was rejected because it drops table semantics for AT, and `table-layout: fixed` would silently re-proportion every Author table.
- **Verification split, stated plainly.** Asserted in code: contrast ratios and the colour/token invariant, reduced-motion containment, the skip-link target on every public page, gallery key maths and roving `tabIndex` markup, lightbox wrap/trap maths, the 44px and 14px floors, `overflow-wrap`/`pre` overflow, control boundaries and focus-ring presence. Inspected by hand (no browser harness in this repo, and the spec says not to add one): real Tab order through a page, what a screen reader announces, the actual pixel layout at 360–430px, and the visual result of the new ring and skip link. Rendered markup was additionally checked against a live `next start` (port 3112, temp database): `/zh`, `/zh/feed`, `/zh/archive`, `/zh/search?q=语法`, `/zh/categories`, `/en` all 200 with exactly one `class="skip-link" href="#main-content"` and one `id="main-content"` + `tabindex="-1"`, and the emitted stylesheet carries both `--line` values plus the four motion queries.

Acceptance-box → test map: (1) `src/app/globals-css.test.ts` "the light/dark theme" (six token pairs × both themes) + "control boundaries" + "text colour"; (2) `skip-link.test.tsx` (markup + every public page has a target), `globals-css.test.ts` "visible focus" (global ring, no removed ring without a replacement, gallery cell ring), `post-card.test.tsx` gallery keyboard/`tabIndex`/live-region tests; (3) `lightbox.test.tsx` "lightbox keyboard rules" (wrap + trap) with the Esc/arrow/aria contract asserted in its markup tests, `post-card.test.tsx` "gallery keys"; (4) `globals-css.test.ts` "reduced motion" (containment + the neutraliser); (5) `globals-css.test.ts` "phone width" plus the live markup check.
