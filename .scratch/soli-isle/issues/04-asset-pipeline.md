# 04: Asset pipeline

**What to build:** The Author picks images and they upload immediately, stored in the image volume with generated thumb and display variants plus the original; content references a stable relative address that survives domain and storage changes. The admin asset library lists every uploaded image with its size and where it is referenced; images referenced by nothing are listed separately and deleted only after the Author confirms manually.

**Blocked by:** 01 — Project foundation & ops contract; 03 — Author auth & admin shell

**Status:** ready-for-human

- [x] Selecting an image uploads it immediately, records it (file name, dimensions, byte size, content hash, upload time), and generates a thumb variant (~800 px) and a display variant (~1600 px WebP) while keeping the original.
- [x] Content bodies reference images only by stable relative addresses with no scheme and no domain.
- [x] The asset library shows all uploads with sizes and which content references each; a separate list shows only images referenced by nothing.
- [x] Deleting an unreferenced image requires explicit Author confirmation; nothing is ever auto-deleted.
- [x] A reusable image picker exists for the later content editors to embed.

## Comments

Implemented on the Next.js 15 foundation, with three decisions confirmed with the user before work started: an `asset_reference` table plus `syncAssetReferences` for reference tracking (content tables arrive in 05), `/media/<assetId>/<variant>.<ext>` as the stable address, and jpeg/png/webp/avif/gif uploads up to 25 MB with EXIF-corrected WebP variants (thumb 800 px, display 1600 px) while the original keeps animation.

- **Data**: `asset` (file name, MIME, byte size, dimensions, sha256 content hash, upload time), `asset_variant` (per-variant bytes, dimensions, format; composite key, cascade), `asset_reference` (asset + content kind/id, unique, cascade). Migration `0002_right_leader` generated by `drizzle-kit generate`; the harness schema test now asserts all six tables.
- **Domain**: `src/domain/asset-address.ts` builds/parses the stable address, maps real formats to extensions, refuses non-WebP display/thumb addresses and absolute or malformed input, and extracts unique asset ids from mixed Markdown/ProseMirror bodies.
- **Storage & images**: files live at `<RESOURCE_DIR>/assets/<assetId>/<variant>.<ext>` with temp-file + rename writes; identifiers are validated before any path is built, and uploaded file names stay metadata only. `sharp` sniffs the real format and orientation, generates both variants without enlargement, and copies the original byte-for-byte so GIF animation survives.
- **Services**: `uploadAsset`, `listAssets`, `listOrphanAssets`, `getAssetVariantFile`, `deleteAsset`, `syncAssetReferences` in `src/services/assets.ts`. Uploads validate size/format by decoding; deletion refuses referenced assets and never runs automatically. Files are removed after the record so a disk failure cannot leave a broken record.
- **HTTP**: `GET|POST /api/admin/assets`, `DELETE /api/admin/assets/<id>` each verify the `soli-session` session independently and map failures to 401/404/409/413/415/422; public `GET /media/<id>/<variant>` serves only the exact stored format with an immutable cache header. Address extensions keep the locale middleware from rewriting media paths.
- **Admin**: `/admin/assets` lists every upload with thumbnail, dimensions, byte size, upload time and each referencing content kind/id, plus a separate unreferenced section. Deletion exists only there and needs an in-page confirm/cancel step; errors and 409s are surfaced. `/admin` links to it.
- **Picker**: `src/components/admin/asset-picker.tsx` is a controlled dialog (`open` / `close` / `onSelect(AssetSummary)`) with immediate upload, Esc, focus entry/return and a tab loop, ready for the editors in 09 to embed.
- **i18n & UI**: `admin.assets.*` in both `zh` and `en` (identical structure, `zh` remains the type source); styles use only the existing theme tokens.

Validation: `tsc` 0 errors, `eslint` 0 errors, Vitest 20 files / 164 tests green (38 new across domain, service and HTTP), `next build` succeeds with `/admin/assets`, `/api/admin/assets`, `/api/admin/assets/[assetId]` and `/media/[assetId]/[variant]`. A live `next start` smoke covered unauthenticated redirect, authenticated upload, rendered library HTML, media bytes and headers, delete 204 and post-delete 404. Two review passes found and fixed an animated-image dimension bug (sharp reported the stacked filmstrip height), a non-atomic delete order, an unused injected storage field, and a media format check that sat in the HTTP layer; regression tests cover each.

Accepted scope notes: the app still uses sharp's bundled libvips rather than forcing the system library named in the spec (the Dockerfile's `libvips42` predates this ticket); the picker is not wired into any page until the editor ticket; `content_kind` stays free text until 05/09 start calling `syncAssetReferences`; and a failed best-effort file removal can leave harmless orphan bytes on disk.
