# 08: Post feed

**What to build:** The Author posts short, untitled Posts — body, multiple images, Tags — from a quick admin composer with the same draft/schedule/archive/permanent-delete lifecycle as Articles. Readers see the Feed: Posts in reverse chronological order, first batch server-rendered, a "load older" button appending the next page without changing the URL. Cards show only relative time (hover reveals the exact absolute time), body, a horizontal image gallery (next-image edge peeking, per-image snap, current/total counter, arrow keys), and Tags; over-tall bodies fold with an inline "展开全文". Tapping a Tag filters the Feed. Posts have no standalone page, are noindex, and never enter the sitemap.

**Blocked by:** 04 — Asset pipeline; 07 — Public article reading

**Status:** ready-for-agent

- [x] The composer publishes a Post with body, multiple images, and Tags; a Post has no Slug and no Category.
- [x] Posts share the full lifecycle: draft, scheduled Publish Time judged by the site timezone, archived, permanently deleted with confirmation.
- [x] The Feed renders its first batch server-side; "load older" appends the next page without changing the URL; the control is absent when nothing older exists.
- [x] A card shows only relative time, body, image gallery, and Tags — no avatar, handle, engagement controls, share controls, or per-Post link.
- [x] Relative time is computed once at render and stays fixed; the machine-readable absolute time is emitted; hovering shows the exact time down to the minute.
- [x] The gallery scrolls horizontally with the next image's edge visible, snaps per image, shows a `current/total` counter, supports arrow keys, and opens the shared lightbox on tap.
- [x] Post bodies taller than the fold collapse with "展开全文" that expands in place without a request; the composer shows no character count and enforces no length limit.
- [x] Tapping a Tag shows only Posts carrying that Tag.
- [x] The Feed is noindex, contributes nothing to the sitemap, and no standalone Post page exists.

## Comments

Built as two new tables plus new modules on top of 05/07 — no shared parent table, no second renderer, no second lightbox, no new dependency. Migration `0005_post_feed.sql` adds `post`, `post_translation`, `post_image`, `post_tag`; nothing existing was altered. `src/test/harness.test.ts` now asserts all four tables and their columns.

**Two product positions, taken as given** (both settled before this ticket started, neither "fixed" here): the Feed is locale-strict — a Post is in a Locale's Feed only if it has a translation in that Locale, Content Fallback does **not** apply to the Feed — and there is no Post URL of any kind: no page, no share target, no sitemap entry, no per-card link.

- **Domain (pure, densely tested)**: `feed-cursor.ts` (`encodeFeedCursor`/`decodeFeedCursor` over a versioned base64url token of `(publishTime, id)`, `normaliseFeedPageSize`, `splitFeedPage`), `relative-time.ts` (`relativeTimeParts` thresholds + `Intl.RelativeTimeFormat` label + `formatAbsoluteMinute`, the hardcoded `YYYY-MM-DD HH:mm` site-time hover title), `post-fold.ts` (`postBodyShouldFold`, the 1 px tolerance and the 320 px threshold), and `feed-view.ts` (the card shape the server hands the card — the presentation contract, so `@/http` and `@/components` can both name it without a layering violation). `public-paths.ts` gained `buildFeedPath({ locale, tagSlug? })`.
- **The visibility rule is now literally one function**: `src/services/visibility.ts` → `visibleToReader(publicationState, publishTime, nowIso)`. Ticket 07's `reading.ts` had it inline; `publishedFilter` there now delegates to it and the Feed uses the same function, so the Article lists, search and the Feed cannot drift. That is a three-line change inside `reading.ts` and the only edit to another ticket's service module.
- **Post service** (`src/services/posts.ts`): `createPostDraft`, `getPost`, `listPosts`, `addPostTranslation`, `savePostTranslation` (version + `stale-content` refusal, same contract as Articles), `setPostImages` (attach/reorder/remove in one call — positions rewritten as 0..n-1), `setPostTags`, `publishPost` / `archivePost` / `unarchivePost` / `deletePostPermanently`, `readFeedPage`, `findPostTag`-free (`listTags` is reused for the filter heading). Posts have **no** `article_revision` equivalent, no slug row and no category, by design.
- **Asset references**: `syncPostAssets` writes `asset_reference` rows of kind `post` from the ordered image set *and* the bodies, so an attached image is never offered as an orphan. Removing an image or deleting the Post releases the reference (asserted at the service seam).
- **Permanent delete and tombstones**: a Post leaves no tombstone, because a tombstone exists to answer 410 on a URL and a Post has no URL. The delete path mirrors the Article one otherwise (cascade + explicit `asset_reference` cleanup).
- **The cursor contract**: the load-older endpoint takes `cursor` = the opaque token for the last card the Reader already has (`publishTime` + `id`, base64url, `f1|<publishTime>|<id>`). The service turns it into `publish_time < :t OR (publish_time = :t AND id < :id)` under `ORDER BY publish_time DESC, id DESC`, fetches `pageSize + 1` rows and reports `nextCursor: null` when the extra row is absent — that null is what removes the control. Garbage, tampered or wrong-version tokens are refused with `400 invalid-cursor` rather than silently restarting at the top; a token naming a since-deleted Post still works, because it is only a position.
- **HTTP**: `src/http/posts.ts` — admin create/get/list/PATCH(tags)/PUT images/PUT translation/POST translation/POST publication/DELETE, each verifying the session itself, plus the public `GET /api/public/feed?locale&tag&cursor&limit`. The Json-body helpers (`readLocale`, `readOptionalString`, `readBaseVersion`, `readIdList`, `compact`, `publishTimeFromBody`) moved into `src/http/admin-json.ts` and `http/articles.ts` now imports them instead of keeping its own copies — one wall-clock→site-timezone conversion for both content kinds. Every answer is `no-store`; the Feed page and the endpoint share `feedView`, so the first batch and the appended pages cannot render differently.
- **Feed UI**: `src/app/[locale]/feed/page.tsx` (server, `force-dynamic`, `robots: { index: false, follow: true }`, takes `?tag=`), `src/components/feed.tsx` (first batch arrives as props and is never fetched client-side; "load older" appends with `fetch` and never touches the URL) and `src/components/post-card.tsx` (`PostCard`, `PostGallery`, `PostBody` + `MeasuredPostBody`). The site nav gained a Feed link; the admin home gained a Posts entry.
- **The fold is measured, never stored**: `MeasuredPostBody` paints the body at its natural height, measures `scrollHeight` once in an effect, and only then applies `max-height` + the fade + the inline 展开全文 button. No column, no flag, no request; without JavaScript the body simply reads long instead of being clamped and unreachable. `PostBody` is presentational, which is what lets the markup be asserted without a layout engine.
- **Relative time is a server render product**: `feedView` formats the label once (for the first batch *and* for every appended page) and hands the card `relativeTime` + the machine-readable `publishTime` + the hover `absoluteTime`. Nothing in the browser recomputes it; there is no timer.
- **Gallery**: `display.webp` cells with `srcset` and `data-original`, one row of cells at 85 % of the track (next edge peeking), `scroll-snap-type: x mandatory` + per-cell `scroll-snap-align`, a `current/total` counter driven by scroll position (visible `3/9`, with the localised sentence for screen readers), ArrowLeft/ArrowRight, and a tap that opens ticket 07's `Lightbox` at the tapped index. A swipe does not open it (the click that follows a moved scroll position is ignored). Cells are `aspect-ratio: 4/5` on phones and `16/9` on wider screens with `object-fit: cover` — deliberately different from Article body images, which keep their original ratio.
- **Composer** (`src/components/admin/post-composer.tsx`): the shared TipTap extension list and Markdown-paste handler, the existing `AssetPicker` for images, an ordered image list with move/remove, a Tag picker with inline creation through the existing `/api/admin/tags`, per-Locale version switching plus "add this language version", and the publish panel (publish now / schedule via `datetime-local` read in the site timezone / archive / unarchive / two-step permanent delete). **No character count and no `maxLength` anywhere** — nothing in the composer measures the body.
- **Renderer quirk worth knowing (not introduced here)**: `renderToStaticMarkup`/Next emit `dateTime` and `srcSet` in camelCase in this React version. HTML attribute names are case-insensitive, so browsers parse them as `datetime`/`srcset`; the Article page has emitted `<time dateTime>` since 07. Tests assert these two attributes case-insensitively.
