# Soli Isle — 一个人的多语言博客

## Problem Statement

作者一个人在维护一个个人站点，需要在同一个地方做两件性质不同的事：写**长文**（有标题、有分类、面向搜索引擎与长期引用），和写**短推文**（无标题、按时间倒序被人扫读、不需要分类）。今天没有任何东西承载这件事：工作区是空的，没有仓库、没有代码、没有可部署的产物。而作者明确不想要通常博客系统附带的那一大套东西——不要用户注册、不要评论、不要多作者权限体系；站点上只有一个人能登录，就是作者本人。

同时，作者用不止一种语言写作。这就要求**界面语言**与**内容语言**各自成立且互不干扰：同一个界面语言下，长文有不同语言的版本，短推文也有不同语言的版本，而这些版本由作者自己撰写和维护，不存在机器翻译或自动同步。

既有博客平台在这两件事上都让作者不满意：通用 CMS 的编辑器表达力不足（对照物是思源笔记那类块级编辑器），而静态博客生成器又要求作者在本地用代码编辑器写字、无法承载"随时发一条推文"的意图。最终目标是：**一个自托管、低维护、单作者、多语言、长文与短推文并存并各有其专属阅读形态的站点。**

## Solution

一个用 Docker Compose 自托管的一体化应用，包含两套面向不同读者的界面：

- **公开站**：以界面语言作为 URL 路径前缀。长文有分类树、标签、归档、站内搜索，并且一切设计都为"被搜索引擎收录"服务；短推文是一个纯推文的时间倒序信息流，视觉参考 X（卡片只显示相对时间、正文、横向图片集、标签），面向手机阅读优化，并且**刻意不进入搜索引擎索引、不提供订阅源、不提供单条推文的独立页面**。
- **管理后台**：仅作者可登录（密码 + 服务端会话）。包含一个对照思源笔记体验打造的富文本编辑器（不做块引用/双向链接/属性视图），支持长文与短推文两种内容、多语言版本面板、分类与标签管理、图片上传与资源库、草稿自动保存、发布与定时发布、归档与永久删除、长文版本快照与回滚。

多语言不是"翻译插件"，而是模型的一等事实：`Article` / `Post` 各自拥有按 Locale 拆分的翻译表，唯一约束保证一门语言一个版本；每篇作品自带 `defaultLocale` 决定翻译缺失时显示哪份正文；界面文案由每语言一份 JSON 承载，缺 key 时构建失败而不是静默回退。

## User Stories

### 读者 — 阅读长文

1. 作为读者，我想在首页看到最近发布的长文，以便判断这个站点是否值得继续读。
2. 作为读者，我想按层级分类浏览长文，以便只读我关心的栏目。
3. 作为读者，我想看到文章所属的分类路径（面包屑），以便知道自己在站点的哪个位置。
4. 作为读者，我想点击标签看到同主题的全部长文，以便顺着一个话题读下去。
5. 作为读者，我想按时间浏览全部长文归档，以便系统地翻完历史内容。
6. 作为读者，我想在长文列表里看到标题、摘要、发布时间和所属分类，以便决定点开哪一篇。
7. 作为读者，我想在长文页看到排版良好、图片完整无裁切的正文，以便不受损地获取信息。
8. 作为读者，我想点击正文里的图片放大查看原始尺寸，以便看清截图和图表里的细节。
9. 作为读者，我想在超长竖版图片上看到完整全貌而不是被裁切，以便读到图里的全部信息。
10. 作为读者，我想看到代码块的语法高亮和正确的等宽排版，以便阅读技术内容。
11. 作为读者，我想看到数学公式被正确渲染，以便阅读含公式的文章。
12. 作为读者，我想看到提示块（Callout）和折叠块被正确呈现，以便理解作者的强调结构。
13. 作为读者，我想在长文底部看到上一篇 / 下一篇或相关文章，以便继续阅读。
14. 作为读者，我想用站内搜索按关键词查找长文，以便找回我记得但找不到的那一篇。
15. 作为读者，我想搜索结果高亮我输入的关键词，以便快速判断哪一条是我要的。

### 读者 — 阅读短推文

16. 作为读者，我想在一个信息流里按时间倒序看到短推文，以便像刷时间线一样快速扫读。
17. 作为读者，我想在推文卡片上只看到相对时间、正文、图片和标签，以便不被多余的界面元素干扰。
18. 作为读者，我想让过长的推文显示"展开全文"，以便就地读完而不跳转页面。
19. 作为读者，我想横向滑动一条推文里的多张图片，以便逐张查看图片集。
20. 作为读者，我想在没有滑动时看到下一张图片露出的边缘，以便不学就知道这里可以横滑。
21. 作为读者，我想看到图片集的当前序号和总数（如 `3/9`），以便知道还有多少张。
22. 作为读者，我想点击推文里的图片放大查看，以便看清图片内容。
23. 作为读者，我想在信息流底部点击"加载更早"继续往下读，以便翻到更久以前的推文。
24. 作为读者，我想在推文很少时不看到翻页控件，以便界面保持干净。
25. 作为读者，我想看到推文的相对时间（"3 小时前"），以便立刻感知内容的新鲜度。
26. 作为读者，我想在悬停推文时间时看到精确到分钟的绝对时间，以便确认确切时刻。
27. 作为读者，我想点击推文上的标签筛选出同标签的推文，以便顺着一个话题读。

### 读者 — 多语言

28. 作为读者，我想在页头随时切换界面语言，以便用我习惯的语言阅读。
29. 作为读者，我想在切换语言后留在当前正在读的那篇文章上，而不是被送回首页，以便不丢失阅读位置。
30. 作为读者，我想在目标语言下没有这篇文章时看到原文并收到"暂无该语言版本"的提示，以便仍然读到内容而不是撞上 404。
31. 作为读者，我想在语言切换器上看到哪些语言实际可用，以便不做无效的点击。
32. 作为读者，我想在访问裸域名时被引导到我浏览器语言对应的版本，以便不用手动切换。
33. 作为读者，我想在我手动选择语言后，之后访问裸域名时记住这个选择，以便不必每次重新切换。
34. 作为读者，我想让带语言前缀的链接永远显示该语言对应的内容，以便分享出去的链接在别人机器上不会变成另一种语言。
35. 作为读者，我想在英文信息流里只看到有英文版本的推文，以便信息流不被外语内容污染。
36. 作为读者，我想让分类名和标签名显示为我当前界面语言下的名称，以便导航结构可读。

### 读者 — 显示与无障碍

37. 作为读者，我想在手机上舒适地阅读长文与推文，以便在通勤时浏览。
38. 作为读者，我想让页面跟随我的系统深色模式，以便夜间阅读不刺眼。
39. 作为读者，我想手动切换深浅色并让选择被长期记住，以便不受系统设置限制。
40. 作为读者，我想在页面加载时不被错误的主题闪一下，以便阅读体验不被中断。
41. 作为读者，我想只用键盘完成全部阅读与导航操作，以便不使用鼠标。
42. 作为读者，我想用方向键浏览横向图片集，以便不用触摸屏也能看完全部图片。
43. 作为读者，我想在灯箱里用 Esc 关闭、用方向键翻页，以便全键盘查看图片。
44. 作为读者，我想在浅色和深色模式下都有足够的文字对比度，以便不费力地阅读。
45. 作为读者，我想在开启"减少动态效果"时不再看到非必要的动画，以便不被动画干扰或引发不适。

### 作者 — 登录与安全

46. 作为作者，我想用密码登录管理后台，以便只有我能写内容。
47. 作为作者，我想让站点从结构上不存在"注册第二个人"的路径，以便不必担心权限配置错误。
48. 作为作者，我想让登录失败被限流并留痕，以便暴力破解不奏效。
49. 作为作者，我想让自己的会话可撤销、可全端失效，以便在设备丢失时切断访问。
50. 作为作者，我想在忘记密码时用一条命令行重置，以便不依赖邮件找回流程。
51. 作为作者，我想让后台页面和写接口各自校验会话，以便中间件规则写漏一条也不至于失守。

### 作者 — 写长文

52. 作为作者，我想在富文本编辑器里用标题、加粗、斜体、删除线、下划线、高亮、列表、任务列表、引用、表格、代码块、链接、分隔线、脚注写作，以便不必手写标记语言。
53. 作为作者，我想用斜杠命令插入块，以便不打字也能调出组件。
54. 作为作者，我想粘贴 Markdown 时自动转换格式，以便从别处搬内容过来。
55. 作为作者，我想拖拽重排块，以便调整结构。
56. 作为作者，我想撤销和重做，以便从误操作中恢复。
57. 作为作者，我想插入数学公式，以便写含推导的内容。
58. 作为作者，我想插入提示块和折叠块，以便组织强调与可选内容。
59. 作为作者，我想给长文设置标题、URL 标识、摘要、分类和标签，以便它被正确组织和检索。
60. 作为作者，我想在发布后修改 URL 标识而且旧链接仍然可用，以便调整标题不弄坏外链。
61. 作为作者，我想在发布后修改标题和正文，以便持续修订内容。
62. 作为作者，我想预览发布后的效果，以便确认排版无误。
63. 作为作者，我想在多个语言版本之间切换编写，以便为同一篇长文写多语言内容。
64. 作为作者，我想让每个语言版本拥有自己的标题、摘要和正文，以便各语言表达自然。
65. 作为作者，我想指定这篇作品的原生语言，以便翻译缺失时读者看到正确的那一份。
66. 作为作者，我想删除某个语言的版本而不影响其他语言，以便撤回一个不满意的译文。

## Implementation Decisions

### 运行时与部署

- 单仓库、单容器应用，用 Docker Compose 编排；对外只暴露一个明文 HTTP 端口。
- 技术栈：Next.js 15（App Router）+ React 19 + TypeScript；SQLite + Drizzle ORM（`better-sqlite3` 驱动）。
- 反向代理、TLS、证书、边缘限流、图片静态托管**均由外层自行提供**，不在应用内实现。应用必须满足的接口约定：只监听明文端口；正文与页面内图片一律使用不含域名与协议的相对路径；解析并信任 `X-Forwarded-For` 与 `X-Forwarded-Proto`；全部后台路由集中在 `/admin` 前缀下，登录入口为单一固定路径。
- 镜像基于 `node:24-bookworm-slim`，**显式安装 `libvips`**，不依赖 `sharp` 在安装时自动获取二进制。
- 数据库文件与图片目录分别位于可挂载的卷，备份即打包卷。

### 分层与接缝

- `src/domain/`：纯逻辑，不引入框架与数据库。承载 Locale 解析与降级选择、可见性判定、URL 生成与解析、日期格式化、Slug 规范化、快照修剪策略。
- `src/services/`：应用的唯一接缝。每个操作是一个明确命名的服务函数，入参出参都是普通数据，依赖通过显式注入的上下文（仓储、时钟、资源存储）获得。
- `src/db/`：Drizzle schema、迁移、仓储实现。
- `src/security/`：基础设施封装（如 Argon2id 密码哈希），只被服务层与 CLI 引用，不含业务判断。
- HTTP 层（Route Handlers、Server Components、中间件）：只做解析请求、校验会话、组装响应，不含业务判断。
- 全部写操作走 REST 风格 Route Handlers，**不使用 Server Actions**。理由：保留一个稳定的、可被非浏览器客户端调用的写接口面，供未来的移动端写作应用复用；服务层不感知调用者是谁。

### 身份与安全

- 不存在用户表：认证信息是部署配置（密码哈希置于 `.env`，仓库内只提交示例文件）。
- 密码哈希使用 Argon2id；提供 `hash-password` 与 `reset-password` 两条命令行脚本。
- 会话为服务端记录（`Session` 表），cookie 只存放不可猜的会话标识，`HttpOnly` + `Secure` + `SameSite=Lax`，30 天滚动过期；登出与改密使全部会话失效。
- 登录失败按来源与全局两个维度限流并递增退避，同时写入审计记录。
- 后台页面由中间件保护，**写接口各自独立校验会话**，二者不互相替代。
- 预留 TOTP 两步验证的接口，默认关闭。

### 数据模型

- `Article` 与 `Post` 为两张独立表。共性（发布状态、发布时刻、翻译关系、时间线查询）通过共享的领域类型与共享服务函数复用，不通过共享父表。
- 两者主键均为 ULID。
- `ArticleTranslation`：外键 `articleId` → `Article`，字段含 `locale`；唯一约束 `(articleId, locale)`。
- `PostTranslation`：外键 `postId` → `Post`，字段含 `locale`；唯一约束 `(postId, locale)`。
- 不引入中立的翻译组表，也不引入跨行的翻译标识列：同一作品的全部语言版本由外键本身界定。
- 每篇作品（`Article` 与 `Post` 各一行）持有 `defaultLocale`，创建时按作者当时的界面语言预填、可修改；它决定 Content Fallback 显示哪份正文。
- `Category`：一棵层级树（`parentId`、排序、语言中立的 slug 路径），路径在该树下唯一；`CategoryTranslation(categoryId, locale)` 承载显示名。一篇长文只属于一个分类。
- `Tag` 与 `TagTranslation`：与分类同构，语言中立的 slug 与按 Locale 的显示名。`Article` 与 `Post` 都可挂多个标签。
- `ArticleSlug` 为当前 URL 标识；`ArticleSlugHistory` 记录历史值，旧值必须能到达同一篇长文。永久删除时 slug 保留并进入"永久移除"语义。
- `ArticleRevision` 仅服务长文：发布动作**强制**生成快照；编辑期间按节流生成快照；修剪策略为"保留全部发布快照 + 最近 N 个自动快照"。
- `Asset` 记录上传事实（文件名、尺寸、体量、内容哈希、上传时间、变体信息）；正文只引用稳定的资源地址。

### 语言

- 站点的支持语言集合是**单一配置项**，同时定义界面语言与内容语言：内容语言只能是界面语言的子集，系统内不存在第二处语言列表定义。
- 界面文案：每个 Locale 一份 JSON，按功能域嵌套；默认语言（中文）那份 JSON 是结构真源，由它推导 TypeScript 类型，其余语言必须满足同一类型——缺 key 导致构建失败，不做运行时静默回退。
- 路由以 Locale 前缀承载语言；裸路径按 `Accept-Language` 以临时重定向（非 301）进入某语言，并读取 cookie 中作者/读者上次的选择作为首选。
- **带前缀的 URL 优先级永远高于 cookie**：cookie 只影响裸路径的落点，绝不用于改写一个已带前缀的请求。
- 语言切换器位于页头，行为是把当前 URL 的 Locale 前缀替换为目标语言；目标语言下不存在该作品时，跳转到同路径并由 Content Fallback 接管。
- Content Fallback：请求某作品在某 Locale 下不存在时，显示该作品 `defaultLocale` 的正文，并显示"暂无该语言版本"的提示；语言切换器如实标出哪些语言可用。URL 前缀保持不变。
- Content Fallback **不作用于信息流**：某语言的信息流只显示在该语言下拥有翻译版本的 Post。

### 可索引性

- 长文的一切设计服务于被搜索引擎收录：`/` 与默认语言页面均可索引；各语言版本通过互指声明与规范链接聚合，**只为真实存在的语言版本声明**。
- 降级页（显示的是非请求语言正文）与归档页标记为不索引；搜索页与信息流页标记为不索引。
- 站点地图只包含可索引的长文页面。
- 永久删除的长文链接返回"永久移除"语义（410），区别于普通的未找到（404）。
- 不做 RSS / Atom 订阅源；短推文不提供单条独立页面、不提供可分享入口、不进入站点地图，也不出现在长文的任何列表或信息流中。

### 编辑器

- 富文本编辑器对照思源笔记的**写作体验**，明确**不实现**块级引用、双向链接、块级属性与属性视图/数据库块。
- 能力范围：标题、加粗、斜体、下划线、删除线、高亮、有序/无序/任务列表、引用块、表格、代码块（语法高亮 + 语言标注）、图片、链接、分隔线、脚注、数学公式、提示块、折叠块、Markdown 快捷输入、斜杠命令、粘贴 Markdown 自动转换、块拖拽排序、撤销重做。
- 存储格式：ProseMirror JSON 为唯一真源；保存时同步派生一份 Markdown 存入派生列，供检索、导出与快照使用；渲染时由 JSON 生成页面内容。
- 编辑器中的改动先写入浏览器本地存储（IndexedDB），随后按节流提交到服务端保存为草稿。节流保存**不产生** `ArticleRevision` 快照。
- 本地副本与服务端版本冲突时**不做自动合并**：阻止静默覆盖，提示服务端存在更新版本，由作者选择丢弃本地改动或把本地版本另存为一篇新草稿。

### 图片

- 上传即入库：图片在选择时立刻上传到本地卷并写入 `Asset`，与内容保存解耦；正文引用稳定地址。
- 上传时用 `sharp` 生成 `thumb`（约 800px 宽）与 `display`（约 1600px 宽，WebP）两个变体，并保留原图；正文用 `srcset` 交由浏览器选择。
- 孤儿资源（已上传但无任何内容引用）由后台页面列出，**必须由作者手动确认删除**，不做自动清理。
- 短推文图片集：横向排布、可横滑，每张约占容器宽度 85%（右缘露出下一张）、按张吸附对齐，显示序号与总数；单元格按视口取比例（手机竖版、桌面横版）并以 `cover` 填满；点击进入灯箱查看原始完整比例。
- 长文正文图片：按原始比例完整显示并钳制最大宽度；高宽比超过阈值的超长竖图施以视口高度上限并以 `contain` 呈现；点击进入同一灯箱。

### 公开前台

- 信息流是纯短推文流，长文完全不进入；首屏服务端渲染最近一批推文，底部提供"加载更早"按钮走接口追加下一页，翻页不改变 URL。
- 推文卡片只包含：相对时间、正文、横向图片集、标签。不含头像、显示名、账号名、互动栏（点赞/转推/回复/书签/浏览量）与任何复制链接控件；卡片本身不是进入某条推文的入口。
- 超过一定高度的推文正文在信息流中折叠并显示"展开全文"，点击就地展开，不发起请求、不跳转；折叠判定由渲染时的样式测量完成，不存储标志字段。编辑器内不显示任何字数计数或上限提示，也不设字数上限。
- 相对时间在服务端渲染时计算一次并固定，不做客户端定时刷新；同时输出机器可读的绝对时间属性，并在悬停时显示精确到分钟的绝对时间。绝对时间的格式硬编码、不按 Locale 本地化。
- 长文侧另有独立的首页区块、分类导航与归档页，与信息流平级互为入口。

### 搜索

- 站内搜索只覆盖长文，用数据库 `LIKE` 匹配标题、正文、标签名与分类名；不引入全文索引（FTS5），理由是个人博客的内容总量下不需要，而中文分词会引入持续的维护成本。
- 搜索结果按当前界面语言过滤，规则与信息流一致；搜索页本身不被索引。

### 界面与无障碍

- 深浅色主题：跟随系统偏好，允许手动覆盖并长期记住；主题令牌以 CSS 变量表达，浅色与深色各一套并**分别**满足对比度要求；在文档头部内联一小段脚本读取本地偏好，避免首屏主题闪烁。
- 无障碍基线为 WCAG 2.1 AA 的对比度要求、完整键盘可达、语义化结构、可见焦点指示、跳转到主内容、灯箱的焦点管理与 Esc 关闭、横向图片集的方向键支持，以及在"减少动态效果"偏好下停用非必要动效。
- 移动端只承担阅读：公开页做移动优先适配；管理后台不针对窄屏做编辑优化。未来可能出现的移动端写作应用**不在本次范围内**，但接口形态（见"分层与接缝"）为它保留接入点。

### 时间与时区

- 定时发布按站点时区（单一配置项）判定，不按作者浏览器时区。

## Testing Decisions

**什么是好测试**：只断言外部可观察的行为——给定输入与初始数据，服务返回什么、数据库里留下什么、页面输出包含什么。不针对实现细节写测试：不测私有函数、不测 SQL 语句形状、不测组件内部状态、不断言 Drizzle 生成的查询文本。测试的写法要让"换一种实现但行为不变"时测试继续通过。

**主接缝（服务层）**：绝大多数测试注入一个"内存 SQLite 库 + 固定时钟 + 临时资源目录"的上下文，直接调用服务函数，然后断言返回值与库内状态。选内存 SQLite 而不是假仓储，是因为 SQLite 本身就是内存数据库，用真库比仿真更真实、也更快，且能把唯一约束、级联、事务这类真正会被踩到的行为一并覆盖。这条路覆盖：Locale 解析与降级选择、可见性判定（草稿/定时/已发布/已归档）、Slug 变更与历史重定向、翻译唯一约束、成稿与语言的组合查询、快照生成与修剪、归档与永久删除的语义差异、标签与分类的关联查询、搜索过滤、资源引用扫描。

**纯函数测试**：日期格式化不依赖真实时间（注入固定时钟）、Slug 规范化、URL 生成与解析、信息流分页游标。这些不碰数据库，用例可以密集铺开。

**接口冒烟测试**：数量刻意保持很少，只验证"薄适配器真的薄"——未认证的写请求被拒、认证后的写请求成功、语言前缀路由落到正确语言、永久删除返回的响应语义正确、共享链接的页面头部包含正确的语言互指声明。用真实文件型 SQLite（临时目录）跑，不 mock 数据库。

**迁移测试**：对空库跑全部迁移，断言 schema 与预期一致，保证新环境一次起得来。

**明确不做的**：不为 Drizzle schema 写断言式测试；不做端到端浏览器测试（本次无既有基础，等编辑器交互稳定后再考虑）；不为第三方编辑器扩展的行为写测试。

**既有先例**：仓库当前为空，本次即为测试基础设施的起点。建议 Vitest 作为测试运行器，并附带一个"建内存库 + 跑迁移 + 播种少量数据"的共享辅助函数，供服务层测试复用。

## Out of Scope

- 用户注册、多作者、角色与权限体系；评论、点赞、转发、收藏、浏览量等任何互动功能。
- RSS / Atom 订阅源；邮件订阅与通知。
- 块级引用、双向链接与反链面板、块级属性、属性视图/数据库块。
- 全文索引与中文分词方案（FTS5 及替代品）。
- 机器翻译、翻译记忆、术语表、自动同步多语言版本。
- 移动端编辑体验优化；未来的移动端写作应用本身（仅保留接口接入点）。
- TLS、证书、反向代理、边缘限流、图片 CDN 与防盗链、HSTS 与安全响应头：由外层提供。
- 站点分析与埋点、SEO 排名工具、广告与变现。
- 数据库从 SQLite 迁移到其他引擎；多实例横向扩展与读写分离。
- 草稿的多人协作、协同编辑、评论批注。

## Further Notes

- 术语以仓库根目录的 `CONTEXT.md` 为准。行文中"长文/推文"是中文行文用法，模型与代码中一律使用 `Article` / `Post`；`Locale` 一词必须与"翻译版本"严格区分（前者是语言，后者是同一作品在某语言下的正文）。
- 有三处决定是分别在多轮里独立做出的，但组合起来构成很强的立场，实现时不要"顺手优化"掉：短推文**既不被索引、也没有独立页面、也没有订阅源**；移动端**只读不写**；标签是作者最初需求里没有、后来加入的维度。
- `Publish Time` 不是一种状态：定时发布由"草稿 + 已设定的发布时刻"派生，实现时不要把它做成第四个状态。
- 图片的两套呈现规则（信息流的固定比例裁切、长文的原始比例完整）是**故意不一致**的，不要为了"统一"而合并。
- 永久删除与普通未找到必须返回不同的响应语义，这是长文"一切为收录服务"策略的一部分。
- 应用不假设自己知道外部域名：任何需要绝对地址的地方（规范链接、语言互指、分享卡片）都从请求头推导或读取单一配置项。
