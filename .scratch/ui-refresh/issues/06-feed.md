# 06: 信息流 — 发丝线流、图集、折叠、加载更早

**What to build:** 让推文流看起来是一条时间线，而不是一叠控件。

- 42rem 单列；每条推文：微标签时间 → 正文 → 横向图集 → 标签；推文之间 1px 发丝线，无卡片边框、无悬停位移。
- 图集：保留 85% 宽、手机 4:5 / 桌面 16:9、12px 圆角、`3/9` 序号、方向键与灯箱。
- 正文折叠：高度阈值与 `展开全文` 保留，渐变遮罩改用新的背景 token。
- 底部「加载更早」改为居中幽灵胶囊；标签筛选移到页头。
- 时间仍是服务端渲染的相对时间 + 机器可读的绝对时间 + 悬停精确到分钟。

**Blocked by:** 01, 02

**Status:** resolved

- [ ] 40 条推文的页面在手机上仍只横向滚动图集，不滚动整页。
- [ ] 图集键盘操作、序号朗读、灯箱焦点管理未被视觉改动破坏。
- [ ] 折叠与展开不发起请求、不改变 URL。
- [ ] 不存在任何「卡片可点」的暗示：没有整卡链接、没有悬停位移、没有复制链接按钮。

## Comments

信息流是**流**：发丝线已经足够分隔，卡片框会让每条 140 字的推文看起来像一个需要操作的面板。悬停反馈同理——spec 明确推文卡片不是入口，给它加反馈就是在骗读者点击。

## Resolution

**resolved** — merge `a155a06` (分支 `ui/06-feed`；合并时 834 测试)。

- 42rem 单列，推文之间 1px 发丝线，**无卡片边框、无悬停位移**（新增断言：`.post-card` 上不得出现 border/border-radius/background/box-shadow，也不得有 `:hover` 规则）。
- 图集保留 85% 宽、手机 4:5 / 桌面 16:9、12px 圆角、`3/9` 序号、方向键与灯箱；`3/9` 对读屏隐藏、另有 aria-live 句子朗读。
- 折叠保留高度阈值与「展开全文」，遮罩用 `--bg`；不发起请求、不改 URL。
- 「加载更早」为居中幽灵胶囊；标签筛选移到页头并成为 kicker。
- 40 条推文的横向滚动实测：360px 下文档宽度等于视口，20 条轨道各自在自身容器内滚动。

**偏离（已记录进 spec 实现备注）**：`.post-time` 保留 14px 而非常规 kicker 的 10px —— spec 的 10px、ticket 01 的「14px 旧断言仍生效」、契约测试的 `READER_TEXT ≥14px` 三者真实冲突，裁决为**可读性下限优先**（时间戳是读者必须读到内容），字距对齐到 kicker 的 0.1em。
