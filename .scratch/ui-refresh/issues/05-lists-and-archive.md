# 05: 列表与归档 — 卡片网格、分类胶囊、月刊式归档

**What to build:** 让分类、标签、搜索变成「浏览」的版式，让归档变成「索引」的版式。

- 分类、标签、搜索：页面头（H1 + 计数）→ 与首页同密度的卡片网格（3/2/1 列）→ 分类页额外一行子分类胶囊；搜索页保留表单、结果摘要与 `<mark>` 高亮，搜索结果的摘要优先显示正文片段。
- 归档：按月分组，月份标签 12px 大写 + 该月计数；组内行式列表用「日期列 + 标题 + 分类」，无封面、无摘要，行间发丝线；日期用等宽数字对齐。
- 面包屑、子分类、标签行的语义结构与链接不变。

**Blocked by:** 01, 02, 03（复用卡片组件）

**Status:** resolved

- [ ] 三处列表共用同一个卡片组件，不为搜索另写一套。
- [ ] 搜索高亮、正文片段、空状态都没有因为换版式而丢失。
- [ ] 归档在 360px 下不横向滚动，长标题换行而非截断。
- [ ] 归档页仍然标记为不索引，搜索页与信息流页同理。

## Comments

归档的密度是功能：读者在这里找「某年某月我写过什么」，封面和摘要是噪音。不要为了「视觉统一」把归档也做成卡片网格。

## Resolution

**resolved** — merge `4ac3163` (分支 `ui/05-lists-and-archive`；合并时 84 文件 / 909 测试)。

- 分类、标签、搜索共用 `ArticleGrid` → `ArticleCard`（一个 prop 映射 `articleCardProps`，来自首页）；`ArticleList` 删除，没有第二套卡片。`ArticleCard` 的 props 无需扩展——已有的 `snippet` 槽正是搜索要的「正文片段优先」。
- 页面头统一为 H1 + 计数；分类页多一行子分类胶囊（数量 + 44px 胶囊）。
- 归档是**索引**而不是卡片网格：12px 大写月份标签 + 该月计数，组内为「日期列 + 标题 + 分类」的发丝线行，无封面无摘要，日期用等宽数字；360px 不横向滚动，长标题换行。
- 归档 / 搜索 / 信息流的 `noindex` 由测试行为化断言（`robots.index === false`）。
- 顺带修掉评审发现的一类缺陷：列表标题原先是浏览器默认的蓝色下划线链接；现在 `<main>` 内所有链接都从调色板取色。

**已知取舍**：浏览卡片不再渲染标签 chips——首页卡片（spec 的卡片解剖）本来就没有标签槽，而三处列表必须共用同一张卡；标签链接仍由长文页的标签行与标签页承载。
